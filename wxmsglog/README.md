# 消息存档

把手机上的通知（微信、短信、钉钉……）**全部存到本地**，按应用、按人、按时间筛选，然后一键复制成文本或导出成文件，粘给 AI 做总结。

## 为什么是「通知」而不是「聊天记录」

微信的聊天数据库在 `/data/data/com.tencent.mm/`，只有 root 才能读到，而且加密。任何声称能导出你本地聊天记录的非 root 方案，要么是骗人，要么是在上传你的数据。

这个 App 走的是另一条路：**安卓系统本身允许应用读取通知**（NotificationListenerService，需要你手动授权一次）。微信每来一条消息，系统都会把通知内容交给已授权的应用，这就是数据来源。

代价是清楚的：

- 只能拿到**通知里显示的内容**，微信设成「不显示消息详情」时就只有「你收到 2 条消息」
- **装之前的历史拿不到**，从开启那一刻起才开始记
- 微信自己把多条消息合并成一条通知时，能拿到几条取决于它合并的方式（优先解析 MessagingStyle，能拿到多条）

## 隐私

2.x 版本没有申请 `INTERNET` 权限，数据在系统层面就出不去。

**3.3.0 起这条变了**：为了做「下载 AI 模型」，必须申请 `INTERNET`。放宽之后用两个办法把范围重新收紧：

- 全工程只有 `ModelDownloader.kt` 一处发起网络请求，地址写死在 `ModelCatalog.kt` 里，只指向公开的模型分发节点
- 清单里声明了 `usesCleartextTraffic="false"`，禁掉全部明文 HTTP，请求只能走 TLS，也不存在被劫持到明文地址的余地

所以现在能保证的是「**除模型下载外没有任何出网代码路径**」，而不是「设备物理上没有出网能力」。你不下模型的话，用起来和以前一模一样。

所有数据存在应用私有目录的 SQLite 里，卸载即清除。应用锁用的是系统指纹 / 锁屏密码，**本应用不接触也不保存任何密码**。模型推理由 llama.cpp 在本机跑，消息内容不会发给任何服务器。

## AI 模型（可选）

**模型不打进安装包。** 1.3GB 的 APK 传不动、也换不了；拆出来之后 APK 还是几兆，模型在设置里自己装、自己换、自己删。

设置 → **AI 模型**，两个来源：

| 方式 | 说明 |
|---|---|
| 应用内下载 | Qwen3 0.6B（498MB）或 1.7B（1.3GB），断点续传，断网了下次接着下 |
| 从文件导入 | 手机上已有 `.gguf` 就直接选，会复制进应用目录（`Android/data/com.wxmsglog/files/models/`） |

选中之后到「待办候选页」，顶栏会多出一个 **AI 补漏**：把规则没认出来的消息交给模型再过一遍。

- 默认最多跑 20 条，单条约 0.5~1 秒
- 输出被 GBNF 语法约束成固定 JSON，模型没法「自由发挥」成一段散文
- 用的是 Qwen3 非思考模式，不会先输出一大段推理

**为什么是 Qwen3 不是 DeepSeek**：DeepSeek 开源的最小模型是 R1 蒸馏 1.5B（1.07GB），它是推理模型，每答一句先想几百字，手机上光思考就要十几秒。Qwen3 0.6B/1.7B 是 Apache 2.0，中文原生好，也能关掉思考直接出结果。

## 界面

顶部三个页签：

- **记录** —— 按应用分组，每组一个标题（图标 + 应用名 + 条数 + 一键复制该组），组内按时间倒序
- **按人** —— 同一个列表，改成按发信人 / 群名分组，想「只看张三今天说了什么」时用这个
- **文本** —— 把所有消息拼成一整段可选中文本，长按选中局部，或点下面「复制文本」一次拿走全部

页签下面两个筛选胶囊：

| 胶囊 | 可选项 |
|---|---|
| 应用 | 全部应用 / 具体某个应用（带条数） |
| 时间 | 今天 / 昨天 / 最近 7 天 / 最近 30 天 / 全部时间 / **自定义区间**（起止日期 + 时分，四步选完） |

筛选是全局的：列表、文本框、复制、分享、导出全部跟着它走，**看到的就是复制到的**。筛过之后胶囊变金边，旁边出现「清除筛选」。

底部三个按钮：**复制文本 / 分享 / 更多**（更多里是「导出当前筛选到下载目录」「分段复制」「分享为文件」「分享为文字」「设置」「清空全部记录」）。

### 多选

**长按任意一条消息**进入多选，之后点其他条目加减选择。顶部会出现「已选 N 条 · 复制 · 删除 · 取消」：

- 复制：选中的几条拼成一段文本
- 删除：只删这几条，不影响其他记录（会二次确认）

### 搜索

顶栏放大镜展开搜索框，支持：

- 空格分隔多个词 → **AND**，例如 `顺丰 取件` 同时含这两个词才命中
- 以 `@` 开头 → 只匹配发信人，例如 `@张三`
- 打字 250ms 防抖，不会每敲一个字符查一次库

**文本页签里来了新消息不会自动刷新**，只在顶部浮一个「有新消息 · 点击刷新」。因为一刷新整段文本就被替换，正在拖选准备复制的那段会直接断掉。点提示、或再点一次「文本」页签即可刷新。

## 复制出来长什么样

```
消息记录，共 128 条，来自 2 个应用
时间范围：最近 7 天

# 微信（98 条）

## 2026-10-25
[09:12] 张三: 明天的会改到下午三点
[09:30] 产品群: 李四: 那个方案我看过了，没问题
[10:02] 张三: 记得带上合同

## 2026-10-24
[21:15] 王五: 收到

# 短信（30 条）

## 2026-10-25
[10:20] 1069xxxx: 【顺丰】您的快递已到菜鸟驿站，取件码 8-2-1234
```

先按应用切开、组内再按日期分组，是为了让 AI 能分清「微信聊了什么」和「短信收到了什么」，也比一整坨流水文本好读得多。

### 导出格式

设置里可以选四种，复制、导出、分享都用同一种：

| 格式 | 适合 |
|---|---|
| Markdown | 粘给 AI、写笔记（默认） |
| 纯文本 | 发短信、贴到不支持 Markdown 的地方 |
| CSV | Excel / WPS 直接打开（带 BOM，中文不乱码） |
| JSON | 自己写脚本再处理 |

### 分段复制（给 AI 用）

几万字一次性丢给模型，既超上下文又抓不住重点。**更多 → 分段复制**会按「应用 + 日期」把当前筛选结果切成每段约一万字，弹一个列表让你逐段复制，每段自带「【第 3/12 段】微信 · 2026-10-25」的抬头。

## 待办与提醒

**从消息里生成**：消息页长按选中几条 → 底部「待办」→ 进「生成待办」页，规则先挑一遍，勾选后落库。

规则认三样东西：

| 认什么 | 例子 |
|---|---|
| 明确时间 | 明天下午三点、周五、3 天后、下周三、月底 |
| 截止表述 | 周五前、28 号之前、deadline |
| 祈使动作 | 记得、别忘了、麻烦你、发我、提交、带上 |

认不出时间的也会列出来，长按就能补一个。同一件事重复出现的会自动去重。时间一律按**消息发出的那一刻**往后推算，不是按你看手机的时间。

**AI 补漏**：装了模型之后（见上一节），这一页的顶栏会多一个按钮，把规则没认出来的消息交给端侧模型再看一遍，一次最多 20 条。

**待办页**（首页顶栏那个勾选图标）

- 未完成在上、已完成沉底，两段各有小标题和条数
- 未完成里：有截止时间的按时间升序在前，没时间的垫底，同一时间段的新的在上
- 点左边的圆圈切换完成状态，长按编辑（改文字、改时间、删除）
- 到点弹通知。Android 12 起精确闹钟是特殊权限，没给的话会降级成不精确闹钟——可能晚几十分钟，页面上有黄色提示
- 重启手机后闹钟会自动重排

## 应用锁

设置 → 隐私 → **应用锁（指纹 / 锁屏密码）**：

- 开启、关闭都要先验证一次，避免别人拿到手机顺手关掉
- 验证交给系统，本应用只拿「成功 / 失败」一个结果
- 设备没录指纹也没设锁屏时不允许开启，防止把自己锁在门外
- 验证过一次，本次使用期间不再重复弹（进程被杀后重开会重新验证）

## 保活与「静默失效」

安卓的省电策略会杀后台，**最坑的是杀掉之后不报错**：授权还显示「已开启」，但一条也收不到。所以状态行会写「最近一条 12 分钟前」；超过 24 小时没有新消息时，顶部会出现黄色提示条和「重启监听」按钮。

设置页里还有两项，按提示操作：

1. **忽略电池优化**（直接弹系统授权框）
2. **自启动 / 后台运行**（按机型自动跳到小米、华为、OPPO、vivo 等对应页面，找不到就退到应用详情）

再顺手在多任务界面里把它锁定。另外每次打开 App 都会主动重绑一次监听，比等系统自己拉起更及时。

## 数据管理

| 设置项 | 作用 |
|---|---|
| 保留时长 | 7 / 30 / 90 / 180 / 365 天或永久。到期后启动时自动清一次 |
| 立刻清理旧记录 | 手动删掉 30 / 90 / 180 / 365 天前的记录 |
| 导出全部到「下载」目录 | 不分筛选，整库导出 |
| 分享全部为文件 | 发 `.md` / `.csv` 附件，微信里不会被截断 |
| 清空全部记录 | 删库，不可恢复 |

## 自己编译

仓库里带 GitHub Actions，push 就会自动编译：

**Actions → 编译 APK → 跑完在 Artifacts 里下载 `WxMsgLog`**

CI 会自己装 NDK 27 和 CMake，并把 llama.cpp 按 v0.7.0 拉下来编译，这些都不进仓库。

本地编译需要 JDK 17 + Android SDK 35 + NDK 27 + CMake 3.22.1，**另外要先拉一次 llama.cpp 源码**：

```bash
bash tools/clone_llama.sh
gradle app:assembleRelease
```

第一次构建要编 llama.cpp，比纯 Kotlin 慢十几分钟，之后有缓存就快了。

## 技术实现

| 部分 | 做法 |
|---|---|
| 监听 | `NotificationListenerService`，`exported="true"` + `BIND_NOTIFICATION_LISTENER_SERVICE` 保护 |
| 解析 | 优先 `NotificationCompat.MessagingStyle` 取多条消息（精确时间戳）；否则退回 TITLE + BIG_TEXT / TEXT_LINES |
| 去重 | 按「发信人 + 内容 + 时间」算 SHA-1 做唯一索引，`INSERT OR IGNORE`。微信会反复更新同一个通知，不去重会存成十几条 |
| 存储 | `SQLiteOpenHelper`，单表 + ts / pkg / sender 索引，不引 Room / KSP |
| 查询 | 一个 `queryFiltered(keyword, pkg, sender, from, to, limit, desc)` 统一入口，列表/文本/复制/导出共用，避免「看到的和复制到的不一致」 |
| 应用锁 | `androidx.biometric`，指纹优先、锁屏密码兜底 |
| 导出 | MediaStore 写入「下载」目录，API 29+ 无需存储权限 |
| 分享文件 | `FileProvider`，只暴露 `cache/exports` |
| 剪贴板 | 超过 40 万字符会截断并提示，完整内容走导出 |

## 已知限制

- 微信关闭「通知显示消息详情」时，只能记录到「你收到 N 条消息」
- 图片、语音、表情在通知里本来就没有内容，只能记录到「[图片]」这类占位
- 撤回的消息拿不到
- 被系统拦下的通知（比如你在系统里静音了微信）不会触发监听
- 列表一次最多渲染 500 条（按当前筛选），更早的用时间筛选或导出
- CSV / JSON 只输出数据本身，不写「时间范围」这类抬头；要归档说明请用 Markdown
- AI 待办识别不是万能的：0.6B / 1.7B 这种体量对「这周得把那个报销的事办了」这类含糊表述仍会漏，也可能给出错误的时间。它只是规则的补充，最终还得你看一眼
- 模型推理时是单线程的，跑 20 条大约要十几秒，这期间不能同时点「添加」
- 模型存在 `Android/data/com.wxmsglog/files/models/`，卸载应用会一起删掉，换手机要重新下
